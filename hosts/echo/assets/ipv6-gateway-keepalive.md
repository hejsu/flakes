# Hyper-V 外部虚拟交换机 IPv6 断流排查：Realtek 网卡 NS 减负问题

最近在 Windows 11 宿主机的 Hyper-V 中部署了一台 NixOS 虚拟机。为了直接获取校园网的公网 IPv6
地址，网络采用了外部虚拟交换机桥接模式。

网络拓扑如下：

```text
Campus core gateway (H3C)
       │
Dorm router (Layer 2 bridge)
       │
Windows 11 host (Realtek 2.5GbE physical NIC, MAC: 00:e2:69:...)
       │
Hyper-V External Virtual Switch
       │
NixOS VM (virtual NIC eth0, MAC: 00:15:5d:...)
```

在此拓扑下，外部虚拟交换机相当于一个纯二层网桥，宿主机与虚拟机共享同一个物理网口，但各自拥有独立的 MAC 地址。配置完成后，虚拟机的 IPv6
表现出了奇怪的断流现象。

## 故障现象

局域网内的宿主机、MacBook 和手机的 IPv6 访问均正常，只有 NixOS 虚拟机存在以下问题：

1.  虚拟机通过 `SLAAC` 能够正常获取公网 IPv6 地址。
2.  虚拟机与宿主机之间的 IPv6 通信正常（可 ping 通，可正常连接宿主机的 `135`/`3389` 端口）。
3.  虚拟机访问公网 IPv6（如 `ping -6 2400:3200::1` 或 `curl -6 baidu.com`）完全超时，丢包率 100%。
4.  周期性断流：每次重置虚拟机网卡或重新绑定 IP 后，外网可以短暂连通 20~30 秒，随后准时断开。

## 排查过程

首先排除了虚拟机内部的配置干扰。关闭 NixOS 防火墙并清空 Tailscale 的策略路由后，问题依旧。由于宿主机与虚拟机之间二层通信正常，说明
Hyper-V 内部转发没有问题，故障点应该在物理网卡与外部网关的交互上。

1. **宿主机抓包** 在 Windows 宿主机上使用 `pktmon` 对物理网卡抓包。结果显示，虚拟机发出的 ICMPv6
请求确实通过物理网卡发送到了外部链路上（`Tx` 有计数），但物理网卡没有收到任何回包（`Rx = 0`）。

请求发得出但收不到回包，且每次重置网卡能维持约 30 秒的连通性，这一特征高度吻合二层邻居缓存（NDP）的老化周期。

2. **邻居发现协议（NDP）验证** 在 IPv6 中，当网关向终端转发数据包且本地没有对应的邻居缓存时，会向局域网发送组播 NS（Neighbor
Solicitation，目标 MAC 为 `33:33:ff:xx:xx:xx`）以解析目标 IP 的 MAC 地址；终端收到后回复 NA（Neighbor
Advertisement），网关记录 `(IP, MAC)` 映射后完成转发。

怀疑网关未能正确解析虚拟机的 MAC 地址，我在断流状态下，使用 `ndisc6` 从虚拟机手动向网关发送了一个单播 NS 请求：

```sh
ndisc6 -s <VM public IPv6> fe80::7625:8aff:fe00:f1ab eth0
```

指令执行后，公网 IPv6 立即恢复连通，但同样在持续约 30 秒后再次超时。

## 根本原因

结合上述测试，可以完整还原故障链路：

1.  上游网关的路由和转发功能正常。
2.  当虚拟机使用 `ndisc6` 主动发送单播 NS（或重启网卡触发 `DAD` 报文）时，数据包中携带了虚拟机的源 IP 和源
    MAC。网关收到后被动更新了邻居缓存表，因此在接下来的 30 秒内能够正常将回包转发给虚拟机。
3.  30 秒后网关的邻居表项老化（`Stale/Delay/Probe`），网关重新向局域网发送组播 NS 寻址。
4.  该组播 NS 报文被宿主机物理网卡丢弃，未能送达虚拟机。虚拟机收不到 NS 便不会回复 NA，导致网关寻址失败，最终丢弃外网回包。

检查宿主机的 Realtek 2.5GbE 网卡驱动属性后，确认问题出在硬件的 **NS 减负（NS Offload）** 功能上。

NS 减负的设计初衷是在网卡硬件层面直接拦截并响应 NS 报文，减少对操作系统 CPU 的唤醒。但在 Hyper-V 桥接场景下，Realtek
的网卡固件只维护了宿主机自身的 IPv6 地址与 MAC 映射。当网关发来针对虚拟机 IP 的组播 NS 时，网卡在硬件层将其拦截，比对发现目标 IP
不属于宿主机，便直接在芯片内部将该报文丢弃，没有将其上交至操作系统的 Hyper-V 虚拟交换机。

## 解决办法

无需在虚拟机内编写定时发包的保活脚本，直接在宿主机上关闭网卡的硬件卸载功能即可：

进入 **设备管理器** -> **网络适配器** -> 双击 **Realtek 2.5GbE** 网卡 -> **高级**，找到 **NS 减负（NS Offload）**，将其设置为 **已禁用**。

禁用后，网卡硬件不再拦截 NS 报文，组播包得以正常透传至 Hyper-V 虚拟交换机。虚拟机能够正常收到网关的寻址请求并回复 NA，公网 IPv6
连接恢复长期稳定。
