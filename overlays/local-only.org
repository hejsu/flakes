#+title: Local-only builds for config-generated derivations
#+filetags: :nix:nix-darwin:hjem:substituters:
#+date: 2026-11-06

* Problem

Editing local nix-darwin/hjem configuration is cheap to evaluate, but the
build phase queries remote binary caches for derivations generated from that
configuration. Every edit produces new store paths, so a cache hit is
impossible and each narinfo request is pure latency.

* Baseline measurement

#+begin_src sh
nix build .#darwinConfigurations.rhayader.system --dry-run -vv
#+end_src

| item                 | value |
|----------------------+-------|
| derivations to build |    14 |
| paths to fetch       |    16 |
| narinfo queries      |    29 |

The 16 fetched paths are ordinary packages (ShellCheck, cue, gnutar, ...).
25 of the 29 queries target five config-generated derivations, five
substituters each:

| derivation      | generated by                                                       | queries |
|-----------------+--------------------------------------------------------------------+---------|
| =etc=           | nix-darwin =modules/system/etc.nix=, =pkgs.runCommand=             |       5 |
| =launchd=       | nix-darwin =modules/system/launchd.nix=                            |       5 |
| =hjem-activate= | hjem =modules/nix-darwin/base.nix=, =writeShellApplication=        |       5 |
| =hjem-impure=   | =modules/impure.nix=, =writeShellApplication=                      |       5 |
| =darwin-system= | nix-darwin =modules/system/default.nix=, =stdenvNoCC.mkDerivation= |       5 |

All five appear in "these 14 derivations will be built", so every query
misses. The remaining 4 queries are real: =cue= and =shellcheck=.

* Negative cache

=narinfo-cache-negative-ttl = 86400=. Re-running the same dry-run yields zero
queries, so the waste is not repeated lookups of old paths. It is new hashes
created by config edits. Verification must force re-lookup:

#+begin_src sh
nix build .#darwinConfigurations.rhayader.system --dry-run -vv \
  --option narinfo-cache-negative-ttl 0
#+end_src

* Constraints

- Keep the substituter list. numtide serves llm-agents (flake source and
  =opencode2=); nix-community serves nur/sops. Removing caches trades away
  compatibility. It is not required by this change.
- Do not use global =substitute = false= or =--offline=. That would force the
  16 real packages to build locally.
- =allowSubstitutes= and =preferLocalBuild= are part of the derivation hash.
  Adding them to a cacheable derivation changes its store path and invalidates
  the cache. Apply only to derivations that can never hit a cache.

Measured with =runCommand= variants:

#+begin_src text
runCommand vs runCommandLocal     -> different outPath
runCommand vs +preferLocalBuild   -> different outPath
runCommand vs +allowSubstitutes   -> different outPath
#+end_src

* Options considered

| option                                        | result                                                          |
|-----------------------------------------------+-----------------------------------------------------------------|
| trim substituter list                         | rejected: loses llm-agents/sops cache compatibility             |
| global overlay =runCommand = runCommandLocal= | rejected: changes every nixpkgs path and invalidates all caches |
| =--option substitute false= for system build  | rejected: forces the 16 real packages to build                  |
| reorder substituters                          | no effect: missing paths try every substituter                  |
| per-derivation =allowSubstitutes = false=     | chosen                                                          |

* Implementation

Three changes.

** =system.systemBuilderArgs= (darwin-system)

nix-darwin appends =cfg.systemBuilderArgs= to the toplevel mkDerivation attrs.
=preferLocalBuild = true= is already set upstream.

#+begin_src nix
system.systemBuilderArgs = { allowSubstitutes = false; };
#+end_src

File: =hosts/rhayader/default.nix=.

** Direct =derivationArgs= (hjem-impure)

nixpkgs =writeShellApplication= sets =allowSubstitutes = true; preferLocalBuild = false=.
Override at the call site:

#+begin_src nix
planter = pkgs.writeShellApplication {
  # ...
  derivationArgs = {
    allowSubstitutes = false;
    preferLocalBuild = true;
  };
};
#+end_src

File: =modules/impure.nix=.

** Overlay for upstream-generated drvs (etc, launchd, hjem-activate)

These are generated inside nix-darwin/hjem and expose no injection point. The
overlay wraps the two builders and applies =overrideAttrs= only to matching
names.

#+begin_src nix
final: prev:
let
  localOnly = [ "etc" "launchd" "hjem-activate" ];
  localize = drv: drv.overrideAttrs (_: {
    allowSubstitutes = false;
    preferLocalBuild = true;
  });
in {
  runCommand = name: env: cmd:
    let drv = prev.runCommand name env cmd;
    in if builtins.elem name localOnly then localize drv else drv;

  writeShellApplication = args:
    let drv = prev.writeShellApplication args;
    in if builtins.elem (args.name or "") localOnly then localize drv else drv;
}
#+end_src

File: =overlays/local-only.nix=. Loaded by =flake.nix= through
=mapModules ./overlays import=, then passed to =import nixpkgs { overlays = ...; }=
in =lib/system.nix= and injected into nix-darwin via =nixpkgs.pkgs=.

Two implementation notes:

- =overrideAttrs= is required. Injecting =allowSubstitutes= through
  =runCommand='s =env= appears in =nix derivation show= but Nix still queries the
  path. =overrideAttrs= sets it in the mkDerivation attrs, the same path
  =runCommandLocal= uses.
- The file must be git-tracked. =nix build .#...= exports a git flake and
  ignores untracked files. Without =git add= the overlay is silently absent.

* Verification

#+begin_src sh
nix build .#darwinConfigurations.rhayader.system --dry-run -vv \
  --option narinfo-cache-negative-ttl 0
#+end_src

| item                 | before | after |
|----------------------+--------+-------|
| derivations to build |     14 |    14 |
| paths to fetch       |     16 |    16 |
| narinfo queries      |     29 |     8 |
| local drv queries    |     25 |     0 |

The remaining 8 queries are =cue= and =shellcheck= (2 packages x 2
substituters x 2 passes in the log). No config-generated derivation is
queried.

* Review findings

- Name matching is the weak point. Upstream renames of =etc=, =launchd= or
  =hjem-activate= silently disable the overlay. Mitigation: add a =tests/=
  assertion that =system.build.{toplevel,etc,launchd}.allowSubstitutes == false=,
  so =nix flake check= catches the regression.
- hjem also creates =link-nix-apps= with =writeShellApplication=. It was not
  queried in the baseline. Add it to =localOnly= only if it starts appearing.
- A name collision with an unrelated =runCommand "etc"= is possible but
  unlikely. The "16 fetched paths unchanged" check is the guard.

* Upstream PR plan

1. nix-darwin =modules/system/etc.nix= and =modules/system/launchd.nix=: add
   =allowSubstitutes = false;= to the =pkgs.runCommand= env. =preferLocalBuild=
   is already set on =toplevel=.
2. hjem =modules/nix-darwin/base.nix=: add
   =derivationArgs = { allowSubstitutes = false; preferLocalBuild = true; };=
   to the =hjem-activate= (and =link-nix-apps=) =writeShellApplication= calls.
3. Once both are released, remove =overlays/local-only.nix= and the
   =hjem-activate= entry. Keep =systemBuilderArgs= and =modules/impure.nix=;
   they are first-party and harmless.

Rationale for upstream: these derivations are generated from local
configuration, change on every edit, and can never be substituted. This is the
same reasoning nix-darwin already applies to =preferLocalBuild = true= on
=darwin-system=.
